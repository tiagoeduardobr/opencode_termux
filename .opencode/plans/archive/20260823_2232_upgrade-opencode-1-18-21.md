# Plano: Upgrade OpenCode 1.18.18 → 1.18.21 (direto)

> **Base**: padrão de upgrade documentado em `AI_HANDOVER.md` (seção "Upgrades
> Sequenciais do OpenCode", 8 upgrades anteriores) e plano anterior
> `.opencode/plans/20260716_0859_doc-upgrade-opencode-1-18-2.md`.

## Objetivo

Atualizar o OpenCode (CLI global + plugin npm) de 1.18.18 para 1.18.21 em um
único salto, seguindo o pipeline consolidado do projeto: branch → CLI no proot
→ plugin bump + lock → docs → code review → commit único → merge fast-forward.

Mudanças relevantes trazidas pelas 3 versões:
- **1.18.20 é a mais impactante para este repo**: subagent tool call failures
  tornam-se resumíveis com `task_id`, falhas resumíveis são surfaced (em vez
  de resultado vazio) e permission requests disparados por subagentes passam a
  ser respondidos durante `opencode run` — afeta diretamente o workflow
  multi-agente orquestrado deste projeto.
- 1.18.19/1.18.21: fixes de providers (Qwen, Cerebras, xAI, Go), Cloudflare AI
  Gateway passthroughs, retry ampliado de network errors, Vertex AI REP
  routing — sem impacto no workflow local.

## Escopo

- **Dentro**: CLI global no proot; `.config/opencode/package.json` +
  `package-lock.json`; `AGENTS.md`; `docs/MULTI_AGENT_ORCHESTRATION.md`;
  `docs/SESSION_CONTEXT_20260618.md`; verificação de coerência.
- **Fora**: mudanças em agentes `.md`, skills, scripts (`bin/`, `scripts/`,
  `shell/`), `opencode.json`, `AI_HANDOVER.md` (seu cabeçalho já apontava
  `3497e95` antes deste upgrade — atualização fica para sessão própria),
  PRs (projeto usa merge direto fast-forward).

## Assumptions

1. Branch base: `main` no HEAD atual (`6cc03d2`). O usuário mencionou
   `3497e95`, mas esse commit já foi superado por `6cc03d2` ("docs: sync
   documentation...") — confirmar na revisão do plano.
2. Changelogs 1.18.19–1.18.21 fornecidos pelo usuário são precisos (não há
   breaking change de config; 1.18.16+ ignora campos desconhecidos).
3. Nenhum campo novo obrigatório em `opencode.json` ou frontmatter de agentes.
4. `npm install` do plugin roda no mesmo ambiente do CLI (proot), onde node
   v26.2.0 / npm 11.17.0 estão disponíveis.
5. Data das entradas documentais: 23/08/2026.
6. Um único commit ao final (decisão do usuário), após code review obrigatório.

## Pré-requisito (fora das tasks — workflow task-build)

Criar branch `feature/upgrade-opencode-1-18-21` a partir de `main`
(delegada ao `git-commit`, conforme regra do projeto). Nenhuma task abaixo
executa em `main` diretamente.

## Tasks

### Task 1: Atualizar CLI global no proot

- **Acceptance**: Given OpenCode 1.18.18 instalado globalmente via npm no proot,
  When `npm install -g opencode-linux-arm64@1.18.21 --force` é executado,
  Then `opencode --version` retorna `1.18.21`.
- **Verify**: `opencode --version` (esperado: `1.18.21`)
- **Files**: nenhum no repo (ambiente global do proot)
- **Complexidade**: baixa
- **Comando**: `npm install -g opencode-linux-arm64@1.18.21 --force`

### Checkpoint 1: Runtime atualizado

- Verificar: `opencode --version` = `1.18.21`
- Validação: smoke test leve — `opencode --help` responde sem erro (TUI/web
  completos serão validados implicitamente pela sessão corrente pós-restart;
  config parsing robusto desde 1.18.16 reduz risco aqui)

### Task 2: Atualizar plugin npm + regenerar lock

- **Acceptance**: Given `.config/opencode/package.json` com `"@opencode-ai/plugin": "^1.18.18"`,
  When a dependência é atualizada para `^1.18.21` e `npm install` roda em `.config/opencode/`,
  Then `package-lock.json` registra `@opencode-ai/plugin` e `@opencode-ai/sdk` na versão `1.18.21`.
- **Verify**:
  ```bash
  grep '"^1.18.21"' .config/opencode/package.json
  grep -n '"version": "1.18.21"' .config/opencode/package-lock.json   # plugin + sdk
  ```
- **Files**: `.config/opencode/package.json`, `.config/opencode/package-lock.json`
- **Complexidade**: baixa

## Riscos

| Risco | Probabilidade | Impacto | Mitigação |
|-------|--------------|---------|-----------|
| `npm install -g` falha no proot (rede/registry/arm64) deixando CLI quebrado | Baixa | Alto | Rodar Task 1 isolada com verificação imediata (`opencode --version`); rollback simples: `npm install -g opencode-linux-arm64@1.18.18 --force` |
| Breaking change silenciosa em config/agentes/skills não listada nos changelogs | Baixa | Médio | Smoke test pós-upgrade (Checkpoint 1); changelogs indicam apenas fixes/features aditivas; 1.18.16+ ignora campos desconhecidos no config parsing; restart do opencode obrigatório pós-upgrade (config não é hot-reload) |
| `package-lock.json` dessincronizado (install parcial ou sdk em versão antiga) | Média | Médio | Task 2 verifica plugin E sdk em `1.18.21` no lock antes de prosseguir; se inconsistente, `rm -rf node_modules package-lock.json && npm install` dentro de `.config/opencode/` |

## Ordem de Implementação

1. Pré-requisito: branch `feature/upgrade-opencode-1-18-21` (via git-commit)
2. Task 1 (CLI) → Checkpoint 1 — runtime válido antes de qualquer doc
3. Task 2 (plugin + lock) — independente da Task 1, mas sequencial por validação
4. Tasks 3 e 4 (AGENTS.md, ORCHESTRATION) — descrevem estado final; podem ser paralelas entre si
5. Task 5 (SESSION_CONTEXT) — por último entre as edits, pois lista todos os arquivos alterados
6. Task 6 (verificação) — depende de todas
7. Pós-plano (workflow task-build): code-review OBRIGATÓRIO do diff → commit único (via git-commit) → merge fast-forward em main → delete branch
