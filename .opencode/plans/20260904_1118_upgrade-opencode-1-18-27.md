# Plano: Upgrade OpenCode 1.18.25 → 1.18.27 (direto)

> **Base**: padrão de upgrade documentado em `AI_HANDOVER.md` (seção "Upgrades
> Sequenciais do OpenCode", 10 upgrades anteriores) e plano anterior
> `.opencode/plans/20260827_2301_upgrade-opencode-1-18-23.md`.

## Objetivo

Atualizar o OpenCode (CLI global + plugin npm) de 1.18.25 para 1.18.27 em um
único salto, seguindo o pipeline consolidado do projeto:
branch → CLI no proot → plugin bump + lock → docs → code review → commit único
→ merge fast-forward.

Mudanças relevantes trazidas pelas 2 versões:
- **1.18.26**: fix sessões Claude 5 toleram stale thinking blocks; fix Bedrock
  GPT-5.6 aceitam none reasoning effort; fix Bedrock reasoning e replay mais
  confiáveis; fix timing de tool calls quando tools atualizam metadata em
  execução; fix apply_patch não emite empty move path em permission metadata;
  melhoria Azure CLI sign-in pede resource name diretamente; Desktop: fix
  session renames salvam de forma confiável.
- **1.18.27**: fix default provider header timeouts de 5 minutos; fix default
  streamed chunk timeouts de 5 minutos (false suportado); fix Anthropic
  thinking.blockBinding pode opt-out via config; fix Anthropic thinking block
  binding limitado a Claude 5.1+; fix evita unhandled errors ao cancelar SSE
  reads com timeout.

## Escopo

- **Dentro**: CLI global no proot; `.config/opencode/package.json` +
  `package-lock.json`; `AGENTS.md`; `docs/MULTI_AGENT_ORCHESTRATION.md`;
  `docs/SESSION_CONTEXT_20260618.md`; verificação de coerência.
- **Fora**: mudanças em agentes `.md`, skills, scripts (`bin/`, `scripts/`,
  `shell/`), `opencode.json`, `AI_HANDVER.md` (atualização fica para sessão
  própria, como nos upgrades anteriores), PRs (projeto usa merge direto
  fast-forward).

## Assumptions

1. Branch base: `main` no HEAD atual (`694678d`, já pushado).
2. Changelogs 1.18.26/1.18.27 fornecidos pelo usuário são precisos (não há
   breaking change de config; 1.18.16+ ignora campos desconhecidos).
3. Nenhum campo novo obrigatório em `opencode.json` ou frontmatter de agentes.
4. `npm install` do plugin roda no mesmo ambiente do CLI (proot), onde node
   v26.2.0 / npm 11.17.0 estão disponíveis.
5. Data das entradas documentais: 04/09/2026.
6. Um único commit ao final (decisão do usuário), após code review obrigatório.
7. **5 arquivos modificados no repo** (package.json, package-lock.json, AGENTS.md,
   MULTI_AGENT_ORCHESTRATION.md, SESSION_CONTEXT_20260618.md).

## Tasks

### Task 1: Atualizar CLI global no proot

- **Acceptance**: Given OpenCode 1.18.25 instalado globalmente via npm no proot,
  When `npm install -g opencode-linux-arm64@1.18.27 --force` é executado,
  Then `opencode --version` retorna `1.18.27`.
- **Verify**: `opencode --version` (esperado: `1.18.27`)
- **Files**: nenhum no repo (ambiente global do proot)
- **Complexidade**: baixa
- **Comando**: `npm install -g opencode-linux-arm64@1.18.27 --force`

### Checkpoint 1: Runtime atualizado

- Verificar: `opencode --version` = `1.18.27`
- Validação: smoke test leve — `opencode --help` responde sem erro (TUI/web
  completos serão validados implicitamente pela sessão corrente pós-restart;
  config parsing robusto desde 1.18.16 reduz risco aqui)

### Task 2: Atualizar plugin npm + regenerar lock

- **Acceptance**: Given `.config/opencode/package.json` com
  `"@opencode-ai/plugin": "^1.18.25"`, When a dependência é atualizada para
  `^1.18.27` e `npm install` roda em `.config/opencode/`, Then
  `package-lock.json` registra `@opencode-ai/plugin` e `@opencode-ai/sdk` na
  versão `1.18.27`.
  > **Nota (lição do upgrade 1.18.21→1.18.25)**: O caret `^1.18.25` resolveu
  > para 1.18.25 (que era o latest), mas se houver 1.18.28 no registry,
  > resolveria para 1.18.28 — causando dessincronização CLI/plugin. Usar
  > `^1.18.27` é seguro porque 1.18.27 é o latest atual (confirmado via
  > `npm view`). Se no momento do execute houver versão mais nova, o dev
  > DEVE escalar para o usuário antes de prosseguir.
- **Verify**:
  ```bash
  grep '"^1.18.27"' .config/opencode/package.json
  grep -n '"version": "1.18.27"' .config/opencode/package-lock.json   # plugin + sdk
  ```
- **Files**: `.config/opencode/package.json`, `.config/opencode/package-lock.json`
- **Complexidade**: baixa

## Riscos

| Risco | Probabilidade | Impacto | Mitigação |
|-------|--------------|---------|-----------|
| `npm install -g` falha no proot (rede/registry/arm64) deixando CLI quebrado | Baixa | Alto | Task 1 isolada com verificação imediata (`opencode --version`); rollback simples: `npm install -g opencode-linux-arm64@1.18.25 --force` |
| Breaking change silenciosa em config/agentes/skills não listada nos changelogs | Baixa | Médio | Smoke test pós-upgrade (Checkpoint 1); changelogs indicam apenas fixes/features aditivas; 1.18.16+ ignora campos desconhecidos no config parsing; restart do opencode obrigatório pós-upgrade (config não é hot-reload) |
| `package-lock.json` dessincronizado (install parcial ou sdk em versão antiga) | Média | Médio | Task 2 verifica plugin E sdk em `1.18.27` no lock antes de prosseguir; se inconsistente, `rm -rf node_modules package-lock.json && npm install` dentro de `.config/opencode/` |
| Novo latest do npm (1.18.28+) aparece entre planejamento e execução, causando dessincronização CLI/plugin | Média | Médio | Task 2 inclui verificação explícita: se `npm view` mostra versão > 1.18.27, escalar para o usuário antes de executar `npm install`. Usar versão exata no CLI (`@1.18.27`) para proteger o runtime global |
