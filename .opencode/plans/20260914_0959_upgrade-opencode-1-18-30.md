# Plano: Upgrade OpenCode 1.18.27 → 1.18.30 (direto)

> **Base**: padrão de upgrade documentado em `AI_HANDOVER.md` (seção "Upgrades
> Sequenciais do OpenCode", 10 upgrades anteriores) e plano anterior
> `.opencode/plans/20260904_1118_upgrade-opencode-1-18-27.md`.

## Objetivo

Atualizar o OpenCode (CLI global + plugin npm) de 1.18.27 para 1.18.30 em um
único salto, seguindo o pipeline consolidado do projeto:
branch → CLI no proot → plugin bump + lock → docs → code review → commit único
→ merge fast-forward.

Mudanças relevantes trazidas pelas 3 versões:
- **1.18.28**: session ID como interaction header do GitHub Copilot (request
  tracking); Desktop: fix client ID do desktop na device auth, fix tamanho do
  ícone open-in app.
- **1.18.29**: fix Codex OAuth model filtering reconhece versões GPT inteiras
  (gpt-6); fix gpt-6-astra não aparecia para assinantes OpenAI.
- **1.18.30**: melhoria Astra system prompt para modelos GPT-6; fix Bedrock
  DeepSeek model IDs preservados (incluindo ARN-based); fix Azure provider SDK
  atualizado; fix OpenAI provider SDK atualizado; fix reasoning effort variants
  para GitLab GPT e Claude.

## Escopo

- **Dentro**: CLI global no proot; `.config/opencode/package.json` +
  `package-lock.json`; `AGENTS.md`; `docs/MULTI_AGENT_ORCHESTRATION.md`;
  `docs/SESSION_CONTEXT_20260618.md`; verificação de coerência.
- **Fora**: mudanças em agentes `.md`, skills, scripts (`bin/`, `scripts/`,
  `shell/`), `opencode.json`, `AI_HANDOVER.md` (atualização fica para sessão
  própria, como nos upgrades anteriores), PRs (projeto usa merge direto
  fast-forward).

## Assumptions

1. Branch base: `main` no HEAD atual (`ba6898b`, já pushado; `d241abf` é o
   commit do upgrade 1.18.27, parent do HEAD).
2. Changelogs 1.18.28/1.18.29/1.18.30 fornecidos pelo usuário são precisos
   (não há breaking change de config; 1.18.16+ ignora campos desconhecidos).
3. Nenhum campo novo obrigatório em `opencode.json` ou frontmatter de agentes.
4. `npm install` do plugin roda no mesmo ambiente do CLI (proot), onde node
   v26.2.0 / npm 11.17.0 estão disponíveis.
5. Data das entradas documentais: 14/09/2026. Datas exatas de release de
   1.18.28/1.18.29 não fornecidas pelo usuário → usar "set/2026" na tabela do
   SESSION_CONTEXT (não inventar datas).
6. Um único commit ao final (decisão do usuário), após code review obrigatório.
7. **5 arquivos modificados no repo** (package.json, package-lock.json,
   AGENTS.md, MULTI_AGENT_ORCHESTRATION.md, SESSION_CONTEXT_20260618.md).
8. **Verificação de latest já feita no planejamento** (14/09/2026):
   `npm view opencode-linux-arm64 version` → `1.18.30` e
   `npm view @opencode-ai/plugin version` → `1.18.30`. Re-verificar na execução
   (Task 1) — se houver versão > 1.18.30, escalar para o usuário.

## Tasks

### Task 1: Pre-flight — verificar versões no npm registry

- **Acceptance**: Given OpenCode 1.18.27 instalado e plugin `^1.18.27` no
  package.json, When `npm view opencode-linux-arm64 version` e
  `npm view @opencode-ai/plugin version` rodam, Then ambos retornam `1.18.30`.
  Se qualquer um retornar versão > 1.18.30, **escalar para o usuário** antes de
  prosseguir (lição do upgrade 1.18.21→1.18.25: caret resolveu para versão mais
  nova, causando dessincronização CLI/plugin).
- **Verify**:
  ```bash
  npm view opencode-linux-arm64 version    # esperado: 1.18.30
  npm view @opencode-ai/plugin version     # esperado: 1.18.30
  ```
- **Files**: nenhum no repo (somente leitura do registry)
- **Complexidade**: baixa

### Task 2: Atualizar CLI global no proot

- **Acceptance**: Given OpenCode 1.18.27 instalado globalmente via npm no proot,
  When `npm install -g opencode-linux-arm64@1.18.30 --force` é executado,
  Then `opencode --version` retorna `1.18.30`.
- **Verify**: `opencode --version` (esperado: `1.18.30`)
- **Files**: nenhum no repo (ambiente global do proot)
- **Complexidade**: baixa
- **Comando**: `npm install -g opencode-linux-arm64@1.18.30 --force`

### Checkpoint 1: Runtime atualizado

- Verificar: `opencode --version` = `1.18.30`
- Validação: smoke test leve — `opencode --help` responde sem erro (TUI/web
  completos serão validados implicitamente pela sessão corrente pós-restart;
  config parsing robusto desde 1.18.16 reduz risco aqui)

### Task 3: Atualizar plugin npm + regenerar lock

- **Acceptance**: Given `.config/opencode/package.json` com
  `"@opencode-ai/plugin": "^1.18.27"`, When a dependência é atualizada para
  `^1.18.30` e `npm install` roda em `.config/opencode/`, Then
  `package-lock.json` registra `@opencode-ai/plugin` e `@opencode-ai/sdk` na
  versão `1.18.30`.
  > **Nota (lição do upgrade 1.18.21→1.18.25)**: O caret `^1.18.27` resolveria
  > para a versão mais recente do registry. Usar `^1.18.30` é seguro porque
  > 1.18.30 é o latest confirmado na Task 1. Se no momento do execute houver
  > versão mais nova, o dev DEVE escalar para o usuário antes de prosseguir.
- **Verify**:
  ```bash
  grep '"^1.18.30"' .config/opencode/package.json
  grep -n '"version": "1.18.30"' .config/opencode/package-lock.json   # plugin + sdk
  ```
- **Files**: `.config/opencode/package.json`, `.config/opencode/package-lock.json`
- **Complexidade**: baixa

## Riscos

| Risco | Probabilidade | Impacto | Mitigação |
|-------|--------------|---------|-----------|
| `npm install -g` falha no proot (rede/registry/arm64) deixando CLI quebrado | Baixa | Alto | Task 2 isolada com verificação imediata (`opencode --version`); rollback simples: `npm install -g opencode-linux-arm64@1.18.27 --force` |
| Breaking change silenciosa em config/agentes/skills não listada nos changelogs | Baixa | Médio | Smoke test pós-upgrade (Checkpoint 1); changelogs indicam apenas fixes/features aditivas; 1.18.16+ ignora campos desconhecidos no config parsing; restart do opencode obrigatório pós-upgrade (config não é hot-reload) |
| `package-lock.json` dessincronizado (install parcial ou sdk em versão antiga) | Média | Médio | Task 3 verifica plugin E sdk em `1.18.30` no lock antes de prosseguir; se inconsistente, `rm -rf node_modules package-lock.json && npm install` dentro de `.config/opencode/` |
| Novo latest do npm (1.18.31+) aparece entre planejamento e execução, causando dessincronização CLI/plugin | Média | Médio | Task 1 inclui verificação explícita: se `npm view` mostra versão > 1.18.30, escalar para o usuário antes de executar `npm install`. Usar versão exata no CLI (`@1.18.30`) para proteger o runtime global |
